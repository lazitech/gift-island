# 赠岛本轮开发问题复盘

2026-11-22

## 概览

两轮需求最终都已上线（提交 `27a406a`，部署到 game.anzhelyu.com）。过程比预期慢、反复多：两张卡共跑了 8 轮 worker，集成审查跑了 2 次，其中约一半的返工可以避免。

- **第一轮需求**：去掉“初级”，去掉“AI 思考深度”（固定为“快”），人机对战可选棋盘大小，为 7×7 和 11×11 写一个非深度学习的 AI。
- **第二轮需求**：三种棋盘统一为 入门 / 进阶 / 最强 / 双人；入门在三种棋盘上都用经典 AI；9×9 的进阶改用 step 501 模型，最强仍是 step 521500；7×7、11×11 的进阶和最强显示“正在开发中”。
- **约束**：四个模型文件都要保留，一直没有改动。

返工的原因分四类：沙箱环境限制、Claude 的流程和指令疏漏、代码本身的缺陷、需求中途调整。后面几节逐一说明，最后给出改进建议。

## 环境与沙箱问题

Codex worker 在新建的 worktree 和受限沙箱里工作，缺少项目运行所需的未入库文件和工具。这直接造成了 2 轮 `partial`，并让 1 个界面 bug 漏了过去。

1. **缺 `.venv`、原生扩展和头文件**。`backend/.venv`、`_search*.so` 和存放 Python 头文件的 `backend/.toolchain` 都不在 git 里，系统自带的 Python 3.14 也没有开发头文件。后端 worker 因此编不出原生扩展，完整 pytest 跑不起来，功能写完了也只能报 `partial`。Claude 手动编译、跑完测试后再 `resume`，多了一轮。
2. **无头浏览器崩溃**。前端 worker 调用的 Chromium 还没打开页面就因 crashpad 数据库报错退出。第 1 轮它只做了 `node --check`，漏掉了“隐藏的选项仍然显示”的 bug；第 2 轮因为无法验证而报 `partial`，改动也没提交。两次都是 Claude 用 Playwright 替它验证。
3. **`.git` 只读**。worker 无法自己 `git commit`，提交本应由启动器在 worker 报告完成后完成。这个限制本身没问题，是 Claude 的指令撞上了它（见下一节）。
4. **Sol 审查也跑不了完整测试**。每份审查报告都写着“原生扩展缺失，完整 pytest 无法运行”。Sol 只能用 `uv run --with numpy` 单独测经典 AI，验证不了真实引擎加 HTTP 的完整路径。它的结论没有因此出错，但审查被拖慢了。

自动门禁不受这些限制：它用主 checkout 的 `.venv` 绝对路径，再加 `CPLUS_INCLUDE_PATH` 指向 `.toolchain`，每次都能编译并跑完全部测试。问题在于这条命令只写进了门禁配置，没有告诉 worker。

## 需求调整与耗时

最花时间的是后端卡的棋力调优和两次全量集成审查，而前者最后被证明并不需要。

- **棋力目标定得太高**：经典 AI 的定位其实是入门对手，但卡片要求它“明显打败贪心基线”，还要求跑 20 局对局。仅 11×11 一局就有约 60 手，每手约 1.5 秒，光对局就要十几分钟，还要反复调参。用户说明“不要求棋力，简单就好”之后，改成 2 层 alpha-beta、每步 2500 节点，一轮就完成了。现在每步约 20 ms（7×7）到 60 ms（线上 11×11）。
- **审查本身慢**：Sol 每次审查要自己跑命令、对拍、测时间，一次 10–15 分钟。两张卡都没拿到“通过”，集成审查就把全部代码当作未审内容重审，又加一次复审。
- **需求中途增加**：第一轮集成审查未完成时就来了第二轮需求。Claude 在单独的 worktree 里直接实现，并把两轮一起交给复审，没有再走卡片。这一轮只用了几分钟，当时只在浏览器里自测，由复审把关。

## 改进建议

前 4 条现在就能做，不用改配置；后 2 条要先排查。

- [ ] 写卡片时把门禁用的构建和测试命令原样写进去（`.venv` 绝对路径加 `CPLUS_INCLUDE_PATH`），并注明“不要 git commit，完成后直接报 done”。
- [ ] 开工前先问清验收标准：尤其是 AI 棋力、性能这类要长时间验证的目标，不要自己加码。
- [ ] 小改动（几十行、只动一个模块）由 Claude 直接改、自己在浏览器里测完就上线，不走 Codex 卡片和审查。
- [ ] 审查进行中每 10–15 分钟用中文汇报一次进度；卡片状态和集成审查的关系要当时说清楚。
- [ ] 排查无头 Chromium 的 crashpad 报错。推测是沙箱不允许往默认目录写崩溃数据，可试试把相关目录指到 worktree 内，尚未验证。修好后 worker 就能自己看界面。
- [ ] 让 worker 和 Sol 的沙箱能读到项目的 `.venv` 和 `.toolchain`，这样它们自己就能跑完整测试，不再依赖 Claude 代跑。

另外有一个遗留项：`docs/openapi.json` 里 `/models` 仍没有声明响应结构，可以之后顺手补上。
